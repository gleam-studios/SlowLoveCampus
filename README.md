# SlowLoveCampus

面向成年 Gay 男性的 BL 情侣日常 YouTube Shorts 创作项目。创作方向以现有[创作总纲](创作总纲.md)为准，使用现有角色、场景和音色资产制作视频。

Agent 先读[项目约定](AGENTS.md)，再按[技能索引](SKILLS_INDEX.md)与[视频流程](video-workflow.md)执行。使用规范见下文；不配置人格文档。

## 制作流程与确认节点

1. **一句话剧情**：独立设计一个具体日常活动、一个有趣的 bit 和自然的身体／情感互动，先排除已记录活动及其同义变体。
   **确认1：等待用户确认剧情，再进入服装设计与角色生图。**
2. **服装设计与角色参考图生成**：用 `character-design` 帅哥快速宫格模板，实际附带各自基础头像，在提示词内描述本集“骚里骚气”的 Gay 穿搭并覆盖模板默认黑色短裤，分别直接生成攻、受角色参考板。默认16:9整板，含清晰面部、半身与全身四视，保持已有身份；通过当前 Codex 的原生图片能力生成并复制回本轮工作区。服装采用适合活动的贴身、短款、低腰、露腰、敞穿、局部透肤等设计，突出身材与挑逗感；无需先做服装样衣或单独换装确认。
3. **分镜脚本**：依据已确认剧情与本轮造型设计时间轴、机位、动作、互动、对白、声音与衔接。默认9:16、成片30秒、多镜头，并安排生成片段边界。
   **确认2：连同两张角色参考图提交，等待用户确认分镜与造型，再写提示词。**
4. **视频提示词**：按已确认分镜，匹配基础头像、本轮造型板、场景及需要的音色，提交整片提示词、各生成片段提示词、素材用途与生成规格。
   **确认3：等待用户确认提示词、资产和规格，再生成。**
5. **H3 生成交付**：按已确认内容核对附件和参数，预检后分段提交、查询并下载，再剪辑合成30秒成片，保存各段回执和 taskId，检查并交付实际结果。项目现有 H3 封装单次支持5–15秒。

一句话剧情 → 确认1 → 服装设计与角色参考图生成 → 分镜脚本 → 确认2 → 视频提示词 → 确认3 → 生成交付。

每个确认节点只交付当前阶段结果并等待回复，不提前执行下一阶段。完整制作请求也不跳过三个确认节点；只要求某一步时停在该步。常规完整制作包含本轮两张造型参考板；仅改流程或只做文字时不生图。其他新资产、额外预算、发布等另行授权。

## 使用规范与跨电脑运行

仓库只保存流程文档、技能源码、固定资产、部署脚本和带版本／SHA-256 的下载清单。Python、FFmpeg、平台依赖和 Whisper 模型由首次运行入口自动下载到 `工具/` 对应目录，仅下载当前电脑所需的平台版本，不依赖作者的共享技能库或系统 Python。

Git 克隆本身不会执行安装脚本；克隆完成后第一次运行 `工具/运行.command`（Mac）或 `工具\运行.bat`（Windows x64）即自动部署。首次需要联网获取固定版本，模型本体约3.09GB；后续复用本机已验证的文件和部署状态，不自动升级，也不重复下载。原有完整工具包仍可直接使用。

按脚本剪辑、原声保留、Whisper 台词识别与字幕、可编辑剪映草稿交付，遵循[剪辑流程](edit-workflow.md)；暂不配音或添加 BGM。工具的转录、FFmpeg 和 Python 命令见[工具说明](工具/README.md)。

### 首次使用

1. 将仓库克隆到本机可读写目录，在自己的 Codex 中打开项目。普通 `git clone https://github.com/gleam-studios/SlowLoveCampus.git` 即可，不需要 Git LFS。
2. 安装并启动一次剪映专业版，在剪映设置中确认当前草稿保存位置。
3. Mac 双击 `工具/运行.command`；Windows x64 双击 `工具/运行.bat`。入口会自动下载并校验当前平台的运行环境、依赖、FFmpeg 与模型，然后检查环境，并从剪映实际设置识别、记住草稿位置。也可在 Codex 中要求“按 README 的使用规范检查当前环境”。
4. 有视频生成需求时，使用者在自己的终端通过下列隐藏输入入口设置 RunningHub Key。密钥不放进项目，不通过聊天发送。配置成功不代表账户余额或线上节点已验证。

Mac：

```sh
./工具/运行.command check --load-model
./工具/运行.command python skills/rh-minimax-h3/scripts/credentials.py set
./工具/运行.command python skills/rh-minimax-h3/scripts/credentials.py status
```

Windows PowerShell（命令逐行执行）：

```powershell
.\工具\运行.bat check --load-model
.\工具\运行.bat python skills/rh-minimax-h3/scripts/credentials.py set
.\工具\运行.bat python skills/rh-minimax-h3/scripts/credentials.py status
```

生图优先使用当前 Codex 会话提供的原生图片工具。是否可用取决于使用者的账号、客户端及当前会话；项目不会安装浏览器、迁移登录态或自动改用付费 API。原生能力不可用时，项目内 `codex-imagegen` 仅提供已有 Codex CLI 的能力检查与适用的执行入口，不保证每个账户都能生图。确认1、确认2、确认3继续按[视频流程](video-workflow.md)执行。

### 下载、缓存与 Git 范围

- `工具/部署锁定.json` 固定三平台 CPython、wheel、FFmpeg 及指定提交的 Whisper 文件来源与 SHA-256；部署时不查询最新版本。wheel 采用固定版本与哈希，禁止源码构建。
- `工具/Python/`、`工具/FFmpeg/`、`工具/依赖/`、`工具/Whisper模型/` 和 `工具/.cache/` 都由 Git 忽略，现有本机文件保留。只有部署脚本和来源／锁定清单进入仓库。
- `工作区/` 和 `输出/` 全部是本机内容，不进入 Git；首次部署创建必要目录和空活动排除清单，已有清单不覆盖。新电脑没有其他电脑的活动历史，不能声称已检查项目外历史。
- 下载先写 `.part`，校验通过才发布正式文件；中断后再次运行同一入口可续传。已有文件哈希不同会停止并保留原件，不通过关闭 TLS 校验或静默换源绕过错误。
- 部署缓存保存于 `工具/.cache/`，同一电脑后续运行按本地记录检查文件，无需重新下载。初次下载失败时保留错误交给 Agent；不要覆盖原模型或修改剪映保存位置。
- 只部署环境、不检查剪映时可运行 `./工具/运行.command setup`；Windows 使用 `.\工具\运行.bat setup`。

### 文件引用规则

- 文档链接相对文档自身。资产清单、剪辑清单、新字幕 JSON 和项目回执中的项目文件引用，以项目根目录为基准，统一用 `/` 分隔。
- 拼板辅助脚本回执标记 `path_base: receipt_file`，其中 source 相对回执文件所在目录，移动配置、源图与输出时保留目录关系。
- 新 H3 jobs 标记 `path_base: jobs_file`，每个 `$upload` 相对 jobs 所在目录。例如本轮任务下的 jobs 引用固定头像可写 `../../资产/角色/攻.jpeg`。执行器按 jobs 实际位置解析，移动项目后不需要替换用户名、盘符或根路径。
- 所有新业务脚本通过 `工具/运行.command python` 或 `工具\运行.bat python` 执行；启动器把工作目录固定为实际项目根目录。因此 `资产/...`、`工作区/...` 的含义不随终端启动位置变化。
- 外部素材先复制进本轮工作区，再写相对引用。不要将作者电脑的素材位置、外部缓存或用户目录写进共享配置。
- 媒体工具或原生图片工具必须接收绝对路径时，由当前运行环境临时解析。生成图片必须复制进本轮 `角色参考/`，不能让项目引用停留在 Codex 的外部生成目录。
- 剪映原生草稿格式使用的绝对路径属于本机应用数据。项目里的清单和脚本仍用相对路径，在使用者电脑上重新生成草稿；复制创作项目不会自动带走原电脑剪映里的草稿。
- 历史任务不批量改写；旧 jobs 未标记基准时沿用旧格式。恢复旧任务时先核对原 taskId 和回执，按本任务的相对素材映射恢复，不能重新提交来试探。

### 剪映草稿位置只记在本机

Mac 的记录位于当前用户的 `~/Library/Application Support/SlowLoveCampus/jianying.json`；Windows 位于当前用户的 `%LOCALAPPDATA%/SlowLoveCampus/jianying.json`。这些是各电脑自己的应用配置入口，不是共享项目文件引用，也不随项目发送。

首次自动读取剪映的实际设置，后续始终复用记录中的已有目录，只在该目录下新建本轮草稿子文件夹。代码拒绝指定其他根目录、失效目录及冲突的 `JY_PROJECTS_ROOT`；同名草稿默认拒绝覆盖。

查看本机记录：

```sh
./工具/运行.command drafts
```

用户在剪映中主动更改保存位置后，重新识别并记住：

```sh
./工具/运行.command drafts --refresh
```

Windows 将上面入口换为 `.\工具\运行.bat`。识别失败、出现多个不同配置、目录被移除或无法访问时会停止并说明；不创建猜测目录，也不修改剪映设置。首次无法读取的新版本设置需要针对该版本补充识别，不能用“某目录存在”代替实际配置证据。

### 在 Codex 中开始工作

> 阅读本项目 AGENTS.md、创作总纲.md、SKILLS_INDEX.md 和 README.md，使用项目工具包检查当前电脑环境及已记录的剪映草稿位置。所有项目文件用相对路径引用，凭据只保存在本机。先说明检查结果，再按我本次指定的制作阶段执行，保留三个确认节点。

### 支持与验证范围

目标系统为 macOS 13+ 的苹果芯片／Intel 电脑及 Windows 10/11 x64；Windows ARM 与 Linux 不支持当前部署清单。Windows 需要系统自带 PowerShell 5.1、curl.exe 和 tar.exe；Mac 使用系统 shell、curl、tar 和 plutil 引导项目 Python。当前可实测的是苹果芯片 Mac。Windows / Intel 仍需相应电脑运行首次检查与本地操作才能认定真机通过。相对路径与 Windows 分支的离线测试不代替真机验证，在线账户及实际生图、视频生成也需按授权单独核验。
